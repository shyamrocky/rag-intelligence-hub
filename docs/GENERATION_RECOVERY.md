# Explicit recovery of a stopped native generation run

The owner-approved recovery contract permits one new Q18 request and first requests
for Q19/Q20, preserving the stopped Batch04 and excluding completed Q17. It grants
no automatic retries, source exceptions or permission for other batches.

An exact, allowlisted successor trust policy binds the three-question plan and a
`native-generation-recovery-1.0` contract. The contract identifies the original
sealed native run, consumed authorization-use hash, unchanged question/request/M7/M8
bindings and each question's disposition. A completed, billed, rejected response
can be deliberately retried once only under explicit owner permission. Unknown
provider outcomes or billing cannot be recovered this way. An unexecuted
continuation must have no original question directory or attempt.

The native history check recognizes only that exact sealed parent admission;
all other history checks remain blocking. Original receipts and durable markers
are never deleted, edited or reset. The original full batch reservation remains
counted, and the recovery plan adds its full conservative estimate against the
overall budget. New authorization consumption permanently blocks a second use,
even if interrupted or only partly completed.

The existing authorization schema binds the exact plan, allowlisted policy,
preservation receipt and current implementation. No additional caller-supplied
history-waiver flag exists. The existing live CLI is used with exactly the three
IDs and a separately issued single-use authorization. Source reconstruction,
request equivalence, source-transfer permission, fresh model/token/context/cost
qualification, receipt freshness, one call per question, zero retries and no
fallback remain mandatory. A new invalid response or unknown cost still stops
the run. Raw capture and diagnostics apply before parsing.

For this recovery, the individual cap stays $0.03 and the run ceiling is $0.09,
within the earlier $0.12 Batch04 ceiling; the overall $1.00 cap is unchanged.
Historical estimates are planning data, not fresh provider qualification or invoice
charges. No approval or semantic acceptance is transferred from prior answers.

Exact archived implementation snapshots preserve historical artifact readback.
Reviewed review-only trust transitions may form an explicit hash-checked chain;
each parent/child edge and review contract must match. This mechanism never
authorizes paid execution under an obsolete baseline.
